## Желательные улучшения

- В classes.md метод ApplicationController.getMyApplications обещает показать историю заявителя. В репозитории есть findByApplicant, но в ApplicationService, которому контроллер делегирует запросы, чтение истории не показано. Уточните, как контроллер получает обращения текущего заявителя.
- В classes.md метод CatalogService.getAvailableDivisionsAndSlots возвращает список Slot. В слоте есть только divisionId, поэтому по ответу заявитель не увидит название и адрес места приёма. Покажите, как при выборе времени он получает сведения о подразделении.
- В classes.md метод completeApplication принимает номер записи и дату процедуры и сразу завершает заявку. В use_case.md сотрудник сначала сохраняет отметку о визите (UC15), затем отдельно подтверждает завершение (UC16). Согласуйте модели, чтобы было ясно, когда сохраняется результат и кто подтверждает смену статуса.
