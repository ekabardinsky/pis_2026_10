## [Открыть результаты работ, оценки и автоматы →](results.md)

**Найдите свою команду в [таблице результатов](results.md). Под оценкой каждой лабораторной нажмите «Открыть отчёт и замечания», чтобы узнать, что нужно исправить.**

В отчёте три основных раздела:

- **Резюме** — общий итог проверки.
- **Обязательно исправить** — грубые ошибки, влияющие на оценку.
- **Желательные улучшения** — рекомендации по улучшению работы.

Результаты обновляются после запуска проверки преподавателем, обычно утром. Коммит в вашем репозитории не обновляет таблицу мгновенно. Дата обновления указана над таблицей; дата проверки конкретной работы — в её отчёте.

Если оценка отсутствует, прочитайте статус и отчёт: работа может быть ещё не сдана, репозиторий может быть пустым или недоступным, либо требуется решение преподавателя. Техническая ошибка проверки не является оценкой за работу.

## Что мы делаем

В течение семестра команда проектирует и разрабатывает учебный аналог приложения государственных услуг по своему заданию. Нужно выполнить **все шесть лабораторных**: пять диаграмм и приложение с видеоотчётом. Диаграммы должны соответствовать одной предметной области, согласовываться между собой и с приложением.

Состав команды — **2–3 человека**. Команда из четырёх человек не соответствует требованиям курса. У каждой команды один GitHub-репозиторий. Проверьте название, номер задания и ссылку на репозиторий в [списке команд](groups.json). Если данные отсутствуют или неверны, сообщите преподавателю через Яндекс Мессенджер. Репозиторий должен быть доступен преподавателю для скачивания и проверки.

Темы и предметные процессы описаны в [дорожной карте](domains.md). Сроки процедур внутри дорожной карты относятся к предметной области — сроки сдачи лабораторных приведены ниже.

## Как оформить репозиторий команды

Имена файлов и расположение результатов фиксированы:

```text
.
├── README.md
├── use_case.md
├── er.md
├── system_sequence.md
├── class_sequence.md
├── classes.md
├── solution/                # Исходный код приложения
└── report/                  # Видеоотчёт
```

Каждая диаграмма находится в отдельном Markdown-файле в корне репозитория. Файл содержит **ровно один блок кода `mermaid`**, после которого идут текстовые пояснения к сущностям, ролям, действиям или взаимодействиям. Одной картинки или одного блока без пояснений недостаточно.

Для диаграммы прецедентов используйте `usecase-beta`. Если просмотрщик не поддерживает эту нотацию, используйте просмотрщик с поддержкой Mermaid 12+; сама по себе ошибка старого просмотрщика не означает ошибку в вашей работе.

В `README.md` команды укажите описание проекта, номер задания, состав команды и инструкцию по запуску приложения, включая настройку базы данных.

### Приложение и видео

Приложение должно поддерживать несколько ролей. Их состав определите по своему процессу. Для получателя услуги предусмотрите:

- Регистрацию и вход по номеру телефона и SMS-коду. Допустим постоянный код `123456`.
- Запрос государственной услуги.
- Предоставление дополнительных документов и исправление заявления по запросу сотрудника, если это требуется процессом.
- Получение результата услуги.
- Просмотр истории статусов и ранее оказанных услуг.

Все данные приложения сохраняются в базе данных. Реальные государственные API и SMS-сервисы подключать не требуется.

В `report/` разместите видеофайл с полным сценарием получения услуги и действиями всех реализованных ролей. Пустая папка или ссылка на видео вместо файла не считается видеоотчётом. Автоматическая проверка проверяет наличие видео; демонстрацию функциональности оценивает преподаватель.

## Оценки и автомат

Для диаграмм lab01–lab05:

| Грубых ошибок | Оценка до штрафа |
| --- | --- |
| Нет | 5 |
| Одна | 4 |
| Две | 3 |

Если грубых ошибок три и более, автоматическая проверка сохраняет замечания и передаёт оценку преподавателю. Мелкие замечания к диаграммам балл не снижают.

Для lab06 критерии накопительные:

| Оценка до штрафа | Требования |
| --- | --- |
| 3 | Есть исходный код приложения и обязательный видеоотчёт |
| 4 | Выполнены требования на 3, в коде нет грубых ошибок |
| 5 | Выполнены требования на 4, соблюдён единый читаемый кодстайл |

Без кода или видео lab06 считается несданной.

**Просрочка больше трёх суток (72 часов) — минус один балл за соответствующую лабораторную.** В таблице показана оценка уже с учётом штрафа. Дата сдачи определяется по дате последнего коммита, изменившего файлы этой лабораторной, а не по дате запуска проверки. Исправление файлов лабораторной меняет её дату сдачи.

**Автомат — среднее итоговых оценок всех обязательных лабораторных с округлением вниз:** например, `4,6 → 4`. Он появляется после получения оценок за все шесть работ. До этого «Текущий средний» учитывает только оценённые работы; колонка «Оценено» показывает полноту сдачи.

AI выполняет предварительную проверку. **Окончательную оценку выставляет преподаватель.** Если считаете замечание ошибочным, обратитесь к преподавателю через Яндекс Мессенджер и укажите команду, лабораторную и спорный пункт отчёта.

## Как сдать работу или исправления

1. Добавьте результат в репозиторий своей команды с точным именем и расположением файла.
2. Сделайте commit и push в основную ветку репозитория. Изменения только на вашем компьютере или в другой ветке не попадут в проверку.
3. После обновления [таблицы результатов](results.md) откройте отчёт своей лабораторной.
4. Исправьте пункты из раздела «Обязательно исправить» и отправьте изменения в тот же репозиторий.

Изменённые работы проверяются при следующем запуске. Неизменившиеся работы повторно не проверяются. Полученная итоговая пятёрка сохраняется; её повторную проверку при необходимости запускает преподаватель.
